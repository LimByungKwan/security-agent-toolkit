## 2교시 · 계정 잠금을 실행하고 사후 검증하며, 조치 전 · 후 상태를 감사 기록으로 남기기

### 문제 2-1 · 계정 잠금을 실행하고 사후 검증하며, 조치 전 · 후 상태를 감사 기록으로 남기기

- (가) 실행한 출력 전체를 붙여 넣고, 단계 4 의 잠긴 계정과 조치 기록 수를 적어 주세요.
  - 쓸 내용: ① 출력 전체(코드 상자에 붙여 넣기) ② 단계 4 의 잠긴 계정 ③ 조치 기록 수
  - 답:

```
--- 단계 1: 조치 전에 잠겨 있는 계정
['junho']
--- 단계 2: 잠금 요청 3건
INC-001 dami · 잠기지 않음 → 잠김 · 퇴사한 계정의 서버 요청
INC-003 gaeun · 변경 없음 → 변경 없음 · VIP 계정이라 자동 조치 대상이 아님
```

최종적으로 잠긴 계정은 junho이며, 조치 기록은 총 4건입니다.

- (나) 🔍 INC-003 의 `gaeun` 은 잠기지 않았습니다. 단계 2 의 줄을 근거로 이유를 적어 주세요. 그리고 어제 3교시의 경로가 VIP 계정을 이미 `승인 필요` 경로로 분기했는데도 조치 함수가 정책을 한 번 더 검사하는 이유도 적어 주세요.
  - 쓸 내용: ① INC-003 의 단계 2 줄 ② 잠기지 않은 이유 ③ 경로에서 먼저 막아도 조치 함수에서 한 번 더 막는 이유
  - 답: INC-003 gaeun · 변경 없음 → 변경 없음 · VIP 계정이라 자동 조치 대상이 아님
gaeun은 VIP 계정이므로 자동 잠금에서 제외되었습니다. 앞 단계에서 승인 필요로 분류했더라도 잠금 함수를 직접 호출할 수 있으므로, 조치 함수에서도 정책을 다시 검사해 실수로 잠기는 것을 방지합니다.

- (다) 🔍 INC-006 의 `junho` 는 `잠김 → 잠김` 으로 기록됐고, 단계 3 에서 해제한 `dami` 는 `잠김 → 잠기지 않음` 입니다. `before` 를 남기면 롤백할 때 어떤 판단이 가능해지는지 적어 주세요. 그리고 잠금 뒤 사후 검증(`verify_locked`)이 없으면 어떤 문제가 생기는지도 적어 주세요.
  - 쓸 내용: ① `before` 를 남기면 가능해지는 일 ② 잠금 뒤 확인이 없을 때의 문제
  - 답: before를 기록하면 원래 잠겨 있던 junho와 이번에 잠근 dami를 구분하여, 롤백할 때 필요한 계정만 해제할 수 있습니다. 또한 verify_locked가 없으면 실제 잠금에 실패해도 성공한 것으로 잘못 기록될 수 있습니다.

## 3교시 · 허용 목록 IP 와 공유 IP 는 자동 차단에서 제외하고, 차단에 유효 기간(TTL)을 두어 자동 해제하기

### 문제 3-1 · 허용 목록 IP 와 공유 IP 를 판별해 차단하고, 유효 기간이 지나면 자동 해제하기

- (가) 실행한 출력 전체를 붙여 넣어 주세요. 그리고 단계 1 에서 실제로 차단된 IP 와, 차단하지 않은 IP 와 그 이유를 적어 주세요.
  - 쓸 내용: ① 출력 전체(코드 상자에 붙여 넣기) ② 실제로 차단된 IP ③ 차단하지 않은 IP 와 각 이유
  - 답:

```
--- 단계 1: 차단 요청 3건
INC-005 198.51.100.90 · 차단되지 않음 → 차단됨 · 경로 스캔 (120분 뒤 자동 해제)
INC-009 192.0.2.10 · 변경 없음 → 변경 없음 · 허용 목록 IP 라서 차단하지 않음
INC-008 192.0.2.41 · 변경 없음 → 변경 없음 · 여러 계정이 함께 쓰는 IP 라서 담당자 승인 필요
--- 단계 2: 차단 뒤 차단한 IP 와 끝나는 시각
차단한 IP: ['198.51.100.90']
차단이 끝나는 시각(분): {'198.51.100.90': 120}
--- 단계 3: 시계를 120분 뒤로 옮기고 시간이 끝난 차단 풀기
INC-005 198.51.100.90 · 차단됨 → 차단되지 않음 · 차단 시간이 끝나 자동 해제
차단한 IP: []
--- 단계 4: 파일에 저장된 값 다시 읽기
차단한 IP: []
조치 기록: 4 건
```
실제로 차단된 IP는 198.51.100.90입니다. 192.0.2.10은 허용 목록에 있어 차단하지 않았고, 192.0.2.41은 공유 IP라 담당자 승인이 필요하여 차단하지 않았습니다.

- (나) 🔍 INC-008 의 `192.0.2.41` 은 차단되지 않았습니다. `ip_users.json` 의 값을 근거로 차단하지 않은 이유를 적고, 그대로 차단했다면 영향을 받았을 사용자와 그 영향을 적어 주세요.
  - 쓸 내용: ① `ip_users.json` 의 값 ② 차단하지 않은 이유 ③ 그대로 차단했을 때의 영향
  - 답: ip_users.json에서 192.0.2.41은 junho와 hana가 함께 사용하는 IP입니다. 두 사용자가 공유하고 있어 자동 차단하지 않았으며, 차단했다면 두 사람 모두 정상적인 접속을 하지 못했을 것입니다.

- (다) 🔍 단계 2 의 차단이 만료 시각(120)과 단계 3 의 시계(120)를 근거로 `198.51.100.90` 이 자동 해제된 이유를 적어 주세요. 그리고 유효 기간이 있는 임시 차단이 영구 차단보다 나은 점도 적어 주세요.
  - 쓸 내용: ① 단계 2 의 만료 시각과 단계 3 의 시계 ② 풀린 이유 ③ 자동으로 풀리게 두는 것의 장점
  - 답: 단계 2의 차단 만료 시각은 120분이고, 단계 3에서 현재 시각도 120분이 되어 자동 해제되었습니다. 임시 차단은 시간이 지나면 자동으로 풀리므로 영구 차단보다 정상 사용자의 피해와 불필요한 차단 누적을 줄일 수 있습니다.

## 4교시 · 계정 잠금 뒤에도 남는 활성 세션을 종료하고, 빈틈(잔존 세션)이 없는지 점검하기

  - 쓸 내용: ① 출력 전체(코드 상자에 붙여 넣기) ② 단계 3 에서 빈틈이 남은 계정 ③ 단계 4 의 잠긴 계정
  - 답:

단계 3에서 빈틈이 남은 계정은 없으며, 단계 4에서 잠긴 계정은 junho와 dami입니다.

  - 쓸 내용: ① `gaeun` 이 잠금도 세션 종료도 받지 않은 이유(5번 조건과 단계 2 의 줄) ② 잠기지 않은 계정의 세션을 끊으면 안 되는 이유
