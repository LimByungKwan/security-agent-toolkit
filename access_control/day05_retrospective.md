# 3과목 총정리 (BK · 2026-11-02(월))

## 상황 1 · 새 직원이 들어옴 (본보기)
- 원인: 데이터 문제입니다. hana 가 입사했는데 `users.json` 에 hana 가 아직 없습니다. 시스템은 사용자 파일에 없는 사람의 요청을 모두 「등록되지 않은 사용자」로 거부합니다.
- 고칠 파일: `config/users.json`
- 어떻게 고치나요: 새로 넣습니다. hana 를 `"hana": {"role": "sales", "employed": true}` 로 `users.json` 에 적습니다. `role` 은 hana 가 맡을 일에 맞는 역할로 정합니다.
- 고친 뒤 확인: hana 의 요청을 다시 판정해서 「등록되지 않은 사용자」가 사라지는지 봅니다.

## 상황 2 · 퇴사자 계정으로 요청이 계속 들어옴 (본보기)
- 원인: 데이터가 정리되지 않았습니다. dami 는 퇴사했는데 dami 의 항목이 `users.json` 에 그대로 남아 있어서 같은 시도가 계속 들어옵니다. `employed` 가 `false` 이면 요청은 거부되지만, 남은 항목 때문에 퇴사자 계정 점검에는 계속 걸립니다.
- 고칠 파일: `config/users.json`
- 어떻게 고치나요: dami 의 `"employed"` 가 `true` 로 남아 있다면 먼저 `false` 로 바꿉니다. 이미 `false` 이면 그대로 두고, dami 의 항목 전체를 `users.json` 에서 지웁니다.
- 고친 뒤 확인: 같은 요청이 「등록되지 않은 사용자」로 거부되고, 퇴사자 계정 점검이 통과로 바뀌는지 봅니다.
- 더 써 보고 싶은 것(선택): `check_permission` 이 퇴사 여부를 역할 확인보다 먼저 보는 이유는 무엇일까요?

## 상황 3 · 다른 팀 업무를 잠시 지원함
- 원인: seoyeon에게 월말 정산 업무에 필요한 권한이 없는 데이터 문제입니다.
- 고칠 파일: `config/exceptions.json`
- 어떻게 고치나요: 승인 절차를 거쳐 `SETTLE:QUERY` 임시 예외를 추가하고 만료 시각을 설정합니다.
- 고친 뒤 확인: 만료 전에는 허용되고 만료 후에는 거부되는지 확인합니다.

## 상황 4 · 새 권한이 필요함
- 원인: 권한 요청과 승인 절차가 정해지지 않은 규칙 문제입니다.
- 고칠 파일: `req_create.py`, `req_review.py`, `req_grant.py`, `config/sla.json`
- 어떻게 고치나요: 요청서를 생성하고 담당자가 승인한 뒤 권한을 부여합니다. 처리 기한은 4시간으로 관리합니다.
- 고친 뒤 확인: 요청 상태가 `reviewing → approved → granted`로 변경되고 처리 기한을 지켰는지 확인합니다.

## 상황 5 · 안 쓰는 권한이 쌓임
- 원인: 오래 사용하지 않은 권한이 정리되지 않은 데이터 문제입니다.
- 고칠 파일: `config/users.json`, 역할 권한 데이터, `config/exclude_list.json`
- 어떻게 고치나요: 90일 초과 미사용 권한을 점검하고, 필요한 권한은 회수 제외하며 불필요한 권한은 승인 절차를 거쳐 회수합니다.
- 고친 뒤 확인: 회수한 권한은 거부되고 회수 제외 권한은 유지되는지 확인합니다.

## 상황 6 · 민감한 권한을 회수해야 함
- 원인: 민감한 권한을 확인 없이 회수하면 정상 업무에 영향을 줄 수 있는 절차 문제입니다.
- 고칠 파일: `revoke_plan.py`, `revoke_approve.py`, `revoke.py`
- 어떻게 고치나요: 회수 계획을 세우고 민감하거나 영향이 큰 권한은 승인받은 뒤 회수합니다.
- 고친 뒤 확인: 승인된 권한만 회수되었는지 확인하고 `revocation_log.json`의 실행 이력을 점검합니다.

## 상황 7 · 새벽 외부 접속, 그리고 정상 직원이 계속 거부됨
- 원인: 접속 시간과 위치에 대한 규칙이 부족하거나 실제 업무 환경과 맞지 않는 문제입니다.
- 고칠 파일: `config/conditions.json`
- 어떻게 고치나요: 권한별 허용 시간과 접속 위치를 설정하고, gaeun의 VPN 접속이 업무상 필요한 경우 승인 후 규칙을 수정합니다.
- 고친 뒤 확인: 비정상적인 새벽 외부 접속은 거부되고 승인된 정상 접속은 허용되는지 확인합니다.

## 상황 8 · 매주 어긋남을 확인해야 함
- 원인: 로그와 권한을 수작업으로 점검하여 누락이 발생할 수 있는 관리 문제입니다.
- 고칠 파일: `checklist.py`, `log_summary.py`, `weekly_report.py`, `config/alert.json`
- 어떻게 고치나요: 퇴사자·만료 예외·부서와 역할을 자동 점검하고 로그 집계 및 경고 기준을 적용해 주간 보고서를 생성합니다.
- 고친 뒤 확인: 점검 결과와 거부율이 정확히 계산되고 주간 보고서가 생성되는지 확인합니다.
