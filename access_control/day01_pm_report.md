## 5교시 · 인증과 인가 · 역할 기반 접근통제(RBAC) · 사용자 파일 · 역할 파일

### 문제 5-1 · 사용자 파일과 역할 파일을 만들고 약한 점 따지기

- (가) 🔍 요청 ① ~ ⑥ 의 판정(허용 · 거부)을 적고, 요청 ② 는 인증과 인가 중 어디에서 막히는지, 10/19(월) 사건과 어떻게 이어지는지 적어 주세요.
  - 쓸 내용: ① 「① 허용 · ② … · ⑥ …」 여섯 개 ② 요청 ② 가 막히는 곳(인증 · 인가)과 매트릭스의 칸 ③ 10/19(월) 사건과 이어지는 점
  - 답: ① 허용 · ② 거부 · ③ 허용 · ④ 거부 · ⑤ 거부 · ⑥ 허용입니다. ②는 sales 역할에 SETTLE:QUERY 권한이 없어 인가 단계에서 거부됩니다. 10/19 사건에서는 인가 규칙이 없어 접근이 허용되었습니다.
- (나) 🔍 매트릭스에서 필요 이상으로 보이는 ○ 를 하나 고르고, 그 이유와 그 ○ 가 남아 있을 때의 위험을 적어 주세요.
  - 쓸 내용: ① 고른 ○(역할 · 권한) ② 필요 이상이라고 본 이유 ③ 남아 있을 때의 위험
  - 답: finance의 SALES:QUERY 권한을 검토해야 합니다. 업무에 불필요하다면 최소권한 원칙에 어긋나며, 계정 탈취 시 영업 정보가 노출될 위험이 있습니다.
- (다) 🔍 `dami` 가 퇴사했는데 인사팀 처리가 파일에 이틀 늦게 반영됩니다. 그 이틀 동안 파일의 `dami` 는 `employed` 가 아직 `true` 입니다. `employed` 칸이 아예 없는 파일과 칸이 있는 파일에서 `dami` 의 요청 결과가 어떻게 다르거나 같은가요? 파일은 누가 언제 고쳐야 하나요?
  - 쓸 내용: ① 칸이 없을 때의 결과 ② 칸이 있을 때의 결과 ③ 파일을 고칠 사람과 시각
  - 답: 칸이 없으면 코드에 따라 결과가 달라지며, 안전하게 거부해야 합니다. 칸이 있어도 true이면 접근이 허용될 위험이 있습니다. 인사팀은 퇴사 즉시 통보하고 계정 관리자는 파일을 즉시 수정해야 합니다.

  - 쓸 내용: 「칸 ①: … → 할 수 있는 점검: … / 칸 ②: … → 할 수 있는 점검: …」
  - 답: 칸 ①: department → 할 수 있는 점검: 소속 부서와 역할이 일치하는지 확인합니다.
        칸 ②: updated_at → 할 수 있는 점검: 계정 정보 변경 시각과 실제 기록을 비교합니다.

  - 쓸 내용: ① 판정(허용 · 거부) ② 그 이유(기본 거부)
  - 답: 거부해야 합니다. intern 역할이 roles.json에 없으므로 기본 거부 원칙을 적용합니다.
- (한 줄) 보안 담당에게 보낼 답을 한 문장으로 적어 주세요.
  - 쓸 내용: 보안 담당이 바로 읽을 수 있는 한 문장(무엇을 파일로 옮겼고 퇴사자를 어떻게 다루는지)
  - 답: 사용자와 역할별 권한을 JSON 파일로 정리하고, 퇴사자는 즉시 접근을 차단하도록 관리하겠습니다.
- 이 교시에서 새로 알게 된 것 하나를 적어 주세요.
  - 쓸 내용: 자유롭게
  - 답: 인증은 신원 확인이고, 인가는 권한 확인이며, RBAC는 역할별로 권한을 관리하는 방식임을 알게 되었습니다.

## 6교시 · 권한 판정 함수 `check_permission`

### 문제 6-1 · 권한 판정 함수 `check_permission` 직접 쓰기

- (가) 채우기 전에 실행한 출력 아홉 줄과, 내가 채운 코드를 붙여 넣어 주세요.
  - 쓸 내용: ① 채우기 전 출력 아홉 줄 ② `# ←` 다섯 곳에 채운 코드
  - 답:

```
① 채우기 전 출력 아홉 줄
seoyeon SALES QUERY -> True 허용
seoyeon SETTLE QUERY -> True 허용
junho SETTLE QUERY -> True 허용
junho SALES CHANGE -> True 허용
dami SALES QUERY -> True 허용
minsu SALES QUERY -> False 등록되지 않은 사용자
gaeun ACCOUNT CHANGE -> True 허용
batch-night SETTLE QUERY -> True 허용
tester SALES QUERY -> True 허용

② 채운 코드 다섯 곳
if not USERS[user]["employed"]:
    return False, "퇴사한 계정"

role = USERS[user]["role"]

if role not in ROLES:
    return False, "역할이 없음"

permission = f"{resource}:{action}"

if permission not in ROLES[role]:
    return False, "권한 없음"
```

- (나) 🔍 채운 뒤 실행한 출력 아홉 줄을 붙여 넣고, 거부된 요청마다 6.1 그림의 몇 번 검사에서 걸렸는지 적어 주세요.
  - 쓸 내용: ① 채운 뒤 출력 아홉 줄 ② 거부된 요청마다 걸린 검사 번호
  - 답:

```

② 거부된 요청마다 걸린 검사 번호
```

- (다) 🔍 채우기 전 출력(가)에서 허용되면 안 되는 요청을 모두 고르고, 각각 왜 허용되면 안 되는지 적어 주세요. 검사가 하나뿐인데 왜 이런 일이 생기나요?
  - 쓸 내용: ① 허용되면 안 되는 요청 ② 각각의 이유 ③ 검사가 하나뿐일 때 이런 일이 생기는 이유
  - 답: seoyeon 정산 조회: 영업팀에 정산 조회 권한이 없습니다.

        dami 영업 조회: 퇴사한 계정입니다.

  - 답: [4] 권한 검사 뒤, 최종 허용 전에 추가합니다. 기존 권한이 있더라도 시간 제한을 적용하기 위해서입니다. 거부 이유는 "오후 6시 이후 정산 조회 금지"로 남깁니다.
- (한 줄) 보안 담당에게 보낼 답을 한 문장으로 적어 주세요.
  - 쓸 내용: 보안 담당이 바로 읽을 수 있는 한 문장(무엇을 거부하고 무엇만 허용하는지)
  - 답: 미등록 사용자·퇴사자·역할 및 권한이 없는 요청을 거부하고, 모든 검사를 통과한 요청만 허용하도록 구현하겠습니다.

## 7교시 · 접속 기록 다시 판정하기 · 쓰이지 않는 권한 찾기 · 올리기

### 문제 7-1 · 접속 기록을 다시 판정하며 쓰이지 않는 권한 찾기

- (가) 🔍 실행한 출력에서 허용 · 거부가 각각 몇 건이고 거부된 번호가 무엇인지 적고, 10/19(월) 의 점수 판단(PDP)은 낮의 12 · 14 ~ 17번을 막지 못했는데 RBAC 는 막은 이유를 두 방식이 무엇을 보고 판정하는지 비교해 설명해 주세요.
  - 쓸 내용: ① 허용 · 거부 건수와 거부된 번호 ② 점수 판단이 보는 것 ③ RBAC 가 보는 것 ④ 왜 달라졌는지
  - 답: 허용 7건, 거부 8건이며 거부 번호는 3, 4, 5, 12, 14, 15, 16, 17번입니다. 점수 기반 PDP는 위험 점수로 판단하지만, RBAC는 역할별 권한을 확인합니다. 따라서 낮에도 권한 없는 정산 조회를 거부합니다.
- (나) 🔍 이 결과만으로 「RBAC 를 켜면 정상 업무는 막히지 않는다」고 말할 수 있나요? 이 기록으로 확인되는 것, 확인되지 않는 것, 기록이 하루치뿐이라서 생기는 한계를 적어 주세요.
  - 쓸 내용: ① 말할 수 있는지 ② 확인되는 것 ③ 확인되지 않는 것 ④ 하루치 기록의 한계
  - 답: 단정할 수 없습니다. 기존 기록의 정상 조회 7건이 허용된 것은 확인했지만, 다른 업무까지 허용되는지는 알 수 없습니다. 하루치 조회 기록만으로 모든 업무 상황을 검증하기 어렵습니다.
- (다) 🔍 5-1 (나)에서 필요 이상이라고 고른 ○ 는 이 기록에서도 쓰이지 않았나요? 쓰이지 않은 권한 가운데 줄일 것 하나와 남길 것 하나를 고르고 각각 이유를 적어 주세요(`auditor` 는 (라)에서 다룹니다).
  - 쓸 내용: ① 5-1 (나)의 ○ 가 쓰이지 않았는지 ② 줄일 권한과 이유 ③ 남길 권한과 이유
  - 답: finance의 SALES:QUERY는 사용되지 않았습니다. 업무상 필요하지 않다면 회수하겠습니다. sales의 SALES:CHANGE는 영업 실적 수정에 필요할 수 있으므로 확인 후 유지하겠습니다.
- (라) 🔍 `auditor` 역할은 권한이 모두 「쓰이지 않음」으로 나옵니다. 왜 그런가요? 이 역할을 어떻게 처리할지 적어 주세요.
  - 쓸 내용: ① 모두 쓰이지 않은 이유 ② 처리 방법
  - 답: 기록에 auditor의 요청이 없어서 모든 권한이 미사용으로 나옵니다. 감사 업무의 필요성을 확인하고 장기간 사용하지 않은 권한은 회수하겠습니다.
- (한 줄) 보안 담당에게 보낼 답을 한 문장으로 적어 주세요.
  - 쓸 내용: 보안 담당이 바로 읽을 수 있는 한 문장(몇 건이 막혔고 줄일 후보가 무엇인지)
  - 답: RBAC 재판정으로 8건을 거부했으며, 미사용 권한인 finance의 SALES:QUERY 등을 회수 후보로 검토하겠습니다.
- 이 교시에서 새로 알게 된 것 하나를 적어 주세요.
  - 쓸 내용: 자유롭게
  - 답: 과거 접속 기록을 새로운 권한 규칙으로 재판정하고, 미사용 권한을 찾아 최소권한 원칙을 점검하는 방법을 알게 되었습니다.
