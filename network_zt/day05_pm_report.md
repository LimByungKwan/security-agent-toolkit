## 5교시 · 지연 · 지터 · 손실

### 문제 5-1 · 지연 · 지터 · 손실을 직접 계산하기

- (가) 회선 X 와 Y 의 평균 지연과 지터(이웃한 두 값의 차이의 평균), 회선 Z 의 손실률을 각각 구해 적어 주세요.
  - 쓸 내용: 「X: 평균 … ms · 지터 … ms / Y: 평균 … ms · 지터 … ms / Z: 손실 … %」
  - 답: 평균 30 ms · 지터 1 ms / Y: 평균 26 ms · 지터 38 ms / Z: 손실 40%
- (나) 🔍 평균 지연만 보면 Y 가 더 좋아 보입니다. 화상회의에는 어느 회선이 더 나쁠까요? 왜 그런가요?
  - 쓸 내용: ① 회선 이름 하나 ② 지연 · 지터 숫자를 써서 이유
  - 답: 화상회의에는 회선 Y가 더 나쁩니다. Y는 평균 지연이 26 ms로 X의 30 ms보다 낮지만, 지터는 38 ms로 X의 1 ms보다 매우 높습니다. 따라서 데이터 도착 시간이 불규칙하여 음성이 끊기거나 영상이 멈추는 현상이 발생할 가능성이 높습니다.

### 문제 5-2 · 내 PC 의 ping 으로 지터 구하고 담당자의 보고 평가하기

- (가) `ping -n 10 8.8.8.8` 의 평균 지연과 손실, 그리고 열 개 응답으로 직접 구한 지터를 적어 주세요.
  - 쓸 내용: 「응답 열 개: … / 평균 … ms · 손실 … % / 지터 … ms」
  - 답: 응답 열 개: 35, 36, 35, 35, 35, 35, 36, 36, 36, 35 ms
        평균 지연: 35.4 ms (계산값)
        패킷 손실: 0%
        지터: 0.44 ms
        지터 계산: (1+1+0+0+0+1+0+0+1) ÷ 9 = 0.44 ms
- (나) 위 ping 기록에서 오전과 오후에 **서로 달라진 조건**을 모두 적고, 「무선이 원인」이라고 확정할 수 있는지 적어 주세요.
  - 쓸 내용: ① 달라진 조건 이름을 모두(PC · 연결 방식 · 대상 주소 · 시각 중) ② 「확정할 수 있다 / 없다」와 이유
  - 답: 오전과 오후에 달라진 조건은 PC(PC 1 → PC 2), 연결 방식(무선 → 유선), 대상 주소(203.0.113.10 → 203.0.113.55), 측정 시각(10:00 → 15:00)입니다. 여러 조건이 동시에 달라졌기 때문에 무선이 원인이라고 확정할 수 없습니다.
- (다) 🔍 무선이 원인인지 확인하려면 무엇을 같게 맞추고, 무엇 하나만 바꿔 다시 재야 하나요?
  - 쓸 내용: ① 같게 맞출 조건 ② 바꿀 조건 하나 ③ 몇 번 재는지
  - 답: 같은 PC, 같은 대상 IP, 비슷한 측정 시각과 네트워크 환경을 유지하고 연결 방식만 무선과 유선으로 바꿔 측정해야 합니다. 각각 ping을 10번씩 보내고 여러 차례 반복하여 평균 지연, 지터, 손실률을 비교합니다.
- (한 줄) 고객에게 보낼 답을 한 문장으로 적어 주세요.
  - 쓸 내용: 고객이 바로 읽을 수 있는 한 문장(무엇을 알았고 무엇을 더 확인하는지)
  - 답: 현재 측정에서는 평균 지연 35.4ms, 지터 0.44ms, 패킷 손실 0%로 안정적인 응답을 보였지만, 화상회의 끊김의 정확한 원인을 확인하기 위해 유선과 무선 환경을 동일한 조건에서 추가 비교하겠습니다.
- 이 교시에서 새로 알게 된 것 하나를 적어 주세요.
  - 쓸 내용: 자유롭게
  - 답: 평균 지연이 낮아도 지터가 크면 화상회의가 끊길 수 있다는 것을 알게 되었고, 네트워크 문제의 원인을 찾으려면 다른 조건은 동일하게 유지한 채 한 가지 조건만 바꿔 비교해야 한다는 것을 배웠습니다.

## 6교시 · 코드로 계산과 판정

### 문제 6-1 · 지터 함수 직접 만들기

- (가) 직접 만든 `jitter` 함수를 독스트링과 함께 아래 코드 블록에 붙여 넣어 주세요.
  - 쓸 내용: 독스트링을 쓴 함수를 복사해 아래 코드 블록에 붙여 넣기
  - 답:

```
total = 0  # 1. total 을 0 으로 시작한다
    for i in range(1, len(got)): # 2. for 와 range(1, len(got)) 로 위치 i 를 꺼내, i 번째 값과 바로 앞 값의 차이의 절댓값을 total 에 더한다
        total = total + abs(got[i] - got[i -1])
    return total / (len(got) - 1) # 3. total 을 (got 의 개수 - 1) 로 나눈 값을 리턴한다
```

- (나) 함수를 채운 뒤 실행해 나온 세 줄을 그대로 옮겨 적어 주세요.
  - 쓸 내용: 터미널 출력 세 줄을 복사해 붙여 넣기
  - 답: 회선 A | 지연 21.9 ms | 지터 1.1 ms | 손실 0 %
회선 B | 지연 42.3 ms | 지터 54.3 ms | 손실 0 %
회선 C | 지연 41.0 ms | 지터 1.7 ms | 손실 30 %
- (다) `jitter` 함수의 리턴값은 무엇이고, `measure` 의 어느 줄에서 어떻게 쓰이나요?
  - 쓸 내용: ① 리턴하는 값이 무엇인지 ② 그 값을 받는 줄(`measure` 안)
  - 답: return total / (len(got) - 1), measure 함수의 jitter_value = jitter(got) 줄에서 리턴값을 받아 jitter_value에 저장하고, round(jitter_value, 1)로 소수점 첫째 자리까지 출력합니다.

### 문제 6-2 · 세 회선을 화상회의 기준으로 판정하기

- (가) 세 회선의 판정 결과(적합 · 부적합)와 걸린 기준을 각각 적어 주세요.
  - 쓸 내용: 「A: … / B: … (걸린 기준 …) / C: … (걸린 기준 …)」
  - 답: A: 적합 (지연 21.9ms, 지터 1.1ms, 손실 0%),
  B: 부적합 (걸린 기준: 지터 54.3ms로 기준 30ms 초과),
  C: 부적합 (걸린 기준: 손실률 30%로 기준 1% 초과)
- (나) 회선 C 는 지연과 지터가 작은데도 왜 부적합인가요? 어제(10/15) 오후 문제 5-2 에서 본 것과 연결해 적어 주세요.
  - 쓸 내용: ① C 의 손실률과 기준 ② 손실이 통신에 주는 영향 한 가지
  - 답: 회선 C의 손실률은 30%로 수업 기준인 1%를 초과했기 때문에 부적합입니다. 패킷이 손실되면 TCP에서는 재전송으로 지연이 발생할 수 있고, 실시간 화상회의에서는 음성이 끊기거나 화면이 멈추는 문제가 발생할 수 있습니다.
- (다) 🔍 `ok` 를 `and` 로 이은 이유는 무엇인가요? `or` 로 이으면 회선 B 의 판정이 어떻게 달라지나요?
  - 쓸 내용: ① `and` 로 이은 이유 ② `or` 로 이으면 B 의 판정이 어떻게 달라지는지
  - 답: `and`는 지연, 지터, 손실률 세 기준을 모두 만족해야 적합으로 판정하기 위해 사용합니다. `or`로 바꾸면 한 가지 기준만 만족해도 True가 되므로, 회선 B는 지터가 54.3ms로 기준을 초과했는데도 적합으로 잘못 판정됩니다.
- (한 줄) 고객에게 보낼 답을 한 문장으로 적어 주세요.
  - 쓸 내용: 고객이 바로 읽을 수 있는 한 문장(어느 회선이 되고 안 되는지, 이유 한 가지)
  - 답: 회선 A는 화상회의에 적합하지만, B는 지터가 54.3ms로 높고 C는 패킷 손실률이 30%로 높아 부적합합니다.
- 이 교시에서 새로 알게 된 것 하나를 적어 주세요.
  - 쓸 내용: 자유롭게
  - 답: abs()를 이용하면 이웃한 응답 시간의 차이를 구할 수 있고, and를 사용하면 여러 기준을 모두 만족하는지 확인하여 회선의 적합 여부를 자동으로 판정할 수 있다는 것을 알게 되었습니다.

## 7교시 · tracert · 진단 · 올리기

### 문제 7-1 · tracert 표에서 느려진 구간 찾기

- (가-1) 표 1 에서 지연이 처음 크게 뛴 구간은 몇 번 홉과 몇 번 홉 사이인가요?
  - 쓸 내용: 「… 번 홉과 … 번 홉 사이」 하나
  - 답: 4번 홉과 5번 홉 사이입니다.
- (가-2) 그 구간은 우리 회사 쪽일까요, 바깥(통신사)일까요? 근거를 적어 주세요.
  - 쓸 내용: ① 「사내 / 바깥」 하나 ② 근거(사내 홉의 시간 또는 장비 이름)
  - 답: 바깥(통신사) 구간으로 판단됩니다. 사내 공유기와 방화벽은 각각 1ms, 2ms로 지연이 낮으며, 통신사 중계 장비인 4번 홉에서 6ms였던 시간이 해외 연결 지점인 5번 홉에서 48ms로 크게 증가했기 때문입니다.
- (나) 🔍 표 2 의 4번 홉은 60 ms 로 큰데 실제 장애가 아니라고 봅니다. 그 근거는 무엇인가요?
  - 쓸 내용: ① 4번 홉의 뒤 홉 시간 ② 그것이 무엇을 뜻하는지
  - 답: 4번 홉의 응답 시간은 60ms로 높지만, 다음 5번 홉에서는 7ms, 6번 홉에서는 8ms로 다시 낮아집니다. 따라서 4번 장비가 tracert 응답만 늦게 처리했을 가능성이 있으며, 실제 데이터 전달 구간의 장애라고 단정할 수 없습니다.

### 문제 7-2 · SaaS 접속이 느린 고객 진단하기

- (가) 이 고객의 SaaS 접속이 느린 원인 구간은 어디인가요?
  - 쓸 내용: 「… 번 홉과 … 번 홉 사이」 + 어떤 장비 구간인지
  - 답: 4번 홉(통신사 중계 장비)과 5번 홉(해외 연결 지점) 사이가 지연 증가의 의심 구간입니다. tracert 결과에서 6ms였던 응답 시간이 48ms로 크게 증가하고 이후 홉에서도 비슷한 수준이 유지되기 때문입니다.
- (나) 🔍 그 구간은 우리가 고칠 수 있나요? 고칠 수 없다면 고객에게 무엇을 말하고 무엇을 요청하나요?
  - 쓸 내용: ① 「고칠 수 있다 / 없다」 ② 고객에게 할 말 한 문장 ③ 요청할 곳과 붙일 자료
  - 답: 직접 고칠 수 없는 통신사 외부 구간으로 판단됩니다. 고객에게 사내 구간에서는 큰 지연이 관측되지 않았으며 통신사 해외 연견 구간에서 지연이 증가한 것으로 보인다고 설명하겟습니다. 통신사에 ping 측정값과 tracert 경로 및 지연 증가 구간을 전달하여 회선 상태와 해외 연결 경로 점검을 요청하겟습니다.
- (다) 이 측정은 한 시각의 값입니다. 이 값만으로 원인을 단정할 수 없는 이유와, 추가로 잴 것 한 가지를 적어 주세요.
  - 쓸 내용: ① 단정할 수 없는 이유 한 가지(한 시각의 값) ② 추가로 잴 것 한 가지
  - 답: 한 시각에 측정한 값만으로는 일시적인 혼잡인지 지속적인 장애인지 알 수 없기 때문에 원인을 확정할 수 없습니다. 따라서 다른 시간대에도 같은 목적지를 대상으로 ping과 tracert를 반복 층정하여 지연이 계속 발생하는지 확인해야 합니다.
- (한 줄) 고객에게 보낼 답을 한 문장으로 적어 주세요.
  - 쓸 내용: 고객이 바로 읽을 수 있는 한 문장(우리 구간 상태, 원인 구간, 요청할 곳)
  - 답: 현재 측정에서는 사내 구간의 큰 지연이 확인되지 않았으나 통신사 중계 장비와 해외 연결 지점 사이에서 지연이 증가한 것으로 보여, 측정 자료를 첨부해 통신사에 해당 구간 점검을 요청하겟습니다.
- 이 교시에서 새로 알게 된 것 하나를 적어 주세요.
  - 쓸 내용: 자유롭게
  - 답: tracert는 목적지까지 거치는 장비와 각 홉까지의 응답 시간을 확인하는 도구이며, 특정 홉의 지연만 높다고 무조건 장애가 아니라 이후 홉의 응답 시간까지 비교해야 한다는 것을 알게 되었습니다.

- 세 회선의 판정과 걸린 기준을 적고, 세 숫자의 차이를 정리해 주세요.
  - 쓸 내용: ① A · B · C 의 판정과 걸린 기준 ② 지연 · 지터 · 손실이 각각 무엇을 나타내는지
  - 답: 회선 A: 적합 — 평균 지연 21.9ms, 지터 1.1ms, 손실률 0%로 모든 기준을 만족했습니다.

  회선 B: 부적합 — 지터가 54.3ms로 기준인 30ms를 초과했습니다.

  회선 C: 부적합 — 패킷 손실률이 30%로 기준인 1%를 초과했습니다.

  지연은 데이터가 목적지까지 갔다 돌아오는 데 걸리는 시간이고, 지터는 응답 시간의 변동 정도이며, 패킷 손실은 전송한 패킷 중 응답을 받지 못한 비율입니다.

  화상회의에는 세 수치가 모두 중요하며 수업에서 정한 기준을 모두 만족해야 적합으로 판정합니다.

### 3. 지연 원인 — 문제 7-1 · 7-2

- SaaS 접속이 느린 원인 구간과 그 근거를 적어 주세요.
  - 쓸 내용: ① 원인 구간 ② 근거(tracert 에서 뛴 값) ③ 사내 구간이 정상이라는 근거
  - 답: SaaS 접속 지연이 증가한 의심 구간은 4번 홉(통신사 중계 장비)과 5번 홉(해외 연결 지점) 사이입니다.

  tracert 결과에서 4번 홉의 응답 시간은 6ms였으나 5번 홉에서는 48ms로 크게 증가했고, 이후 6번과 7번 홉에서도 49ms, 50ms로 높은 시간이 유지되었습니다.

  반면 사내 공유기는 1ms, 사내 방화벽은 2ms로 큰 지연이 관측되지 않았습니다. 따라서 사내보다 통신사 외부 구간을 우선 점검할 필요가 있다고 판단했습니다.
