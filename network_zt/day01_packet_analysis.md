### 찾아본 것

- 2.1 표에서 찾아 쓴 TTL 의 뜻과 라우터를 지날 때 바뀌는 방식: 
  - TTL (Time to Live)의 뜻: 패킷이 네트워크상에 영원히 맴돌며 루프를 형성하는 것을 방지하기 위해 설정된 패킷의 유효 수명(최대 거칠 수 있는 라우터 수/홉 수)입니다.

  - 라우터를 지날 때 바뀌는 방식: 패킷이 라우터를 하나 지날 때마다(1홉 이동 시) TTL 값이 1씩 감소합니다. 값이 0에 도달하면 라우터는 해당 패킷을 자동으로 폐기합니다.

### 이 교시에 새로 안 것

- 이 교시에서 새로 알게 된 것:

- **TTL:** 패킷의 무한 루프를 막는 **유효 수명**이며, 라우터를 1개 통과할 때마다 **1씩 감소**합니다.
- **DNS:** `google.com` 같은 이름을 입력하면 패킷 전송 전 **IP 주소로 자동 변환**합니다.
- **실패 구분:**
- `could not find host`: 이름 변환(DNS) 실패로 **보내기도 전에 멈춤**.
- `Request timed out`: IP로 패킷을 **보냈으나 응답이 없음**.
- **자동화:** `ping` 응답 속도를 파이썬으로 해석해 **[정상/느림/실패]** 상태를 자동으로 판정할 수 있습니다.

  - 답: PC 는 같은 망의 게이트웨이에 보내려면 그 MAC 주소를 알아야 해서 ARP 로 물어봅니다. 물어봐서 알아낸 값이라 동적 입니다.

### ⭐ 도전 3-5 · 주소 모양으로 IP 와 MAC 구별하기

- 출력 첫 줄:

### 이 교시에 새로 안 것

- 이 교시에서 새로 알게 된 것:
IP와 MAC의 역할 차이: IP는 네트워크상의 위치(논리적 주소)이고, MAC은 랜카드 고유의 고유 번호(물리적 주소)입니다.

게이트웨이 응답 속도: 게이트웨이(1ms)가 외부 서버(35ms)보다 빠르며, 거리가 가깝고 거쳐 가는 라우터가 적을수록 왕복 시간이 단축됩니다.

ARP(주소 결정 프로토콜): IP 주소만 알고 있을 때 실제 통신을 위해 해당 장비의 MAC 주소를 찾아내는 역할을 하며, 이렇게 자동으로 알아낸 정보는 '동적'으로 등록됩니다.

주소 형태 구별: 점으로 구분된 4자리 숫자는 IP 주소, 하이픈(-)으로 구분된 16진수 6쌍은 MAC 주소로 구별할 수 있습니다.

### 문제 4-5 · 증상으로 층 좁히기

- 증상 ① · ② · ③ 에서 의심되는 층: 1-7층, 2-1~3층, 3-4층 이상
- 증상마다 그렇게 판단한 근거는 무엇인가요?
  - 답: 
  증상 ① 근거: IP 주소(8.8.8.8)로는 ping 통신(3층)이 정상 작동하므로 하위 1~3층 네트워크는 모두 정상입니다. 도메인 이름(google.com)을 IP 주소로 바꾸는 DNS 서비스(7층 응용 계층) 단계에서만 문제가 발생했습니다.

  증상 ② 근거: 내 PC가 속한 같은 네트워크(우리 망)의 관문인 기본 게이트웨이까지도 통신이 안 되므로, 랜선/Wi-Fi 연결(1층), MAC 주소/스위칭(2층), 로컬 IP 설정(3층) 등 기초 네트워크 단절 문제입니다.

  증상 ③ 근거: ping 통신(3층 IP 계층)이 정상 작동하므로 3층까지의 네트워크 연결은 보장됩니다. 따라서 통신 연결 문제가 아니라 해당 웹 서버의 특정 포트(80/443 등, 4층)가 막혔거나 웹 서버 애플리케이션(7층)의 장애일 가능성이 높습니다.

### 찾아본 것

- 4.1 표에서 찾아 쓴 3389 의 위험과 445 를 이용해 퍼진 랜섬웨어:

  - 3389 (RDP, 원격 데스크톱)의 위험: 인터넷에 노출되어 있을 경우 계정 대입 공격(Brute Force), 크리덴셜 스터핑 또는 RDP 취약점을 통해 공격자가 서버에 직접 침투 및 원격 제어권을 탈취할 수 있는 치명적인 위험이 있습니다.

  - 445 (SMB)를 이용해 퍼진 랜섬웨어: 워너크라이(WannaCry) (SMBv1 취약점인 EternalBlue를 악용하여 파일 공유 포트인 445번을 통해 네트워크 내로 빠르게 자가 전파됨)

### 이 교시에 새로 안 것

- 이 교시에서 새로 알게 된 것:
  - 포트와 서비스 파싱: dict.get()을 사용하면 없는 포트 번호(예: 3389)가 들어와도 에러 없이 기본값("모름")을 반환하는 안전한 예외 처리가 가능합니다.

  - 소켓 상태의 차이: LISTENING은 외부 접속을 기다리는 대기 상태(135/RPC, 445/SMB 등)이고, ESTABLISHED는 이미 외부와 연결되어 실제로 데이터를 주고받는 활성 상태입니다.

  - 고위험 포트 보안: 원격 제어 포트(3389/RDP)는 무단 침투 위험이 높고, 파일 공유 포트(445/SMB)는 워너크라이(WannaCry) 랜섬웨어처럼 네트워크 내 자가 전파 통로로 악용될 수 있어 관리 및 차단이 필수적입니다.

## 5교시 · TCP

### 문제 5-1 · 직접 실행해 보기

- 출력 세 줄: True False 443
- 탐지 코드에서 플래그를 `==` 로 검사하면 어떤 일이 생기나요? 둘째 줄을 근거로 설명합니다.
  - 답: 탐지 규칙에서 == 로 쓰면 에러 없이 아무것도 못 잡으므로, 플래그 검사는 in 으로 씁니다.

### 문제 5-2 · TCP 일까 UDP 일까

- ① ~ ⑤ 가 각각 TCP · UDP · ICMP 중 무엇인지: 1:TCP, 2:UDP, 3:TCP, 4:UDP, 5: 둘 다 아님
- ① 사진 파일 보내기가 TCP 인 이유는 무엇인가요?
  - 답: "단 1바이트의 데이터 손실도 없어야 하는 완벽한 신뢰성"이 필요하기 때문입니다.

### 문제 5-3 · 세 번의 순서 맞히기

- 세 패킷의 순서와 방향: (나) 내 PC → 서버 · (다) 서버 → 내 PC · (가) 내 PC → 서버
- 🔍 연결을 맺을 때는 세 번인데, 끝낼 때는 왜 네 번인가요?
  - 답: 내 PC 가 [SYN] 으로 먼저 청하고, 서버는 「받았다(ACK)」와 「나도 연결하자(SYN)」를 한 줄에 실어 답합니다. 내 PC 의 마지막 [ACK] 뒤에 ESTABLISHED 가 됩니다.

### 문제 5-4 · 같은 서버로 간 두 연결은 무엇이 다른가

- 두 연결에서 같은 것 · 다른 것: 외부 주소(목적지 IP · 포트)는 같고 로컬 주소 끝의 포트(임시 포트)만 다르다
- 같은 서버로 간 두 연결을 무엇으로 구별하나요?
  - 답: 연결 하나는 네 값(출발지 IP, 출발지 포트, 목적기 IP, 목적지 포트)으로 구별됩니다. 목적지와 내 IP가 같으니, 내 PC가 연결마다 다른 임시 포트를 골라 구별합니다.

### 이 교시에 새로 안 것

- 이 교시에서 새로 알게 된 것:
  - 파이썬 플래그 검사 규칙: 여러 플래그가 담긴 리스트를 다룰 때는 ==가 아닌 in 연산자를 사용해야 패킷 탐지 오류를 막을 수 있습니다.

  - TCP vs UDP 용도 차이: 파일이나 HTTP 요청처럼 손실 없는 정밀함이 필요한 경우 TCP, 실시간 스트리밍이나 DNS 조회처럼 속도가 중요한 경우 UDP를 사용하며, ping은 ICMP 프로토콜을 사용합니다.

  - Handshake 원리: 연결 시(SYN→SYN,ACK→ACK) 3-way 방식을 쓰고, 종료 시에는 남은 데이터 처리를 위해 FIN과 ACK가 분리되어 4-way 방식을 씁니다.

  - 4연속 식별자: 같은 서버(IP:Port)로 연결을 여러 개 맺어도 내 PC의 출발지 임시 포트 번호가 서로 달라 개별 연결을 구분할 수 있습니다.

  - 통신 방향 및 포트 분석: 클라이언트 임시 포트에서 443(HTTPS) 포트로 향하는 패킷(임시포트 → 443)은 요청, 반대 방향(443 → 임시포트)은 응답 패킷임을 구별할 수 있습니다.

  - 계층별 패킷 헤더 구조: 패킷 상세 정보 창에서 2층(MAC), 3층(IP, TTL), 4층(Port, Flags) 헤더 정보가 위에서 아래로 순서대로 중첩되어 전달됨을 직접 확인하였습니다.

  - 표시 필터(Display Filter)의 동작: dns, udp, tcp.port == 443 등 특정 조건을 지정해 필요한 패킷만 원본 데이터 훼손 없이 선별하여 관제할 수 있습니다.

## 최종 분석 — 7교시에 완성합니다

> 오늘 잡은 **내 HTTP 연결 하나**를 처음부터 끝까지 정리합니다. 위에서 적은 6-3 · 7-1 · 7-2 의 답을 다시 보며 씁니다.

### 1. 연결이 열리는 순간 — 3-way handshake

- 세 줄의 Source → Destination 과 Info:
  1. 내 PC → 서버: [SYN]
  2. 서버 → 내 PC: [SYN, ACK]
  3. 내 PC → 서버: [ACK]
- 세 줄이 오간 뒤 두 컴퓨터는 어떤 상태가 되나요?
  - 답: TCP 연결이 수립되어 **ESTABLISHED(연결 완료)** 상태가 되고, 데이터를 주고받을 수 있습니다.

  - 답: **443번은 HTTPS의 기본 포트**이므로 HTTPS 서비스로 향하는 패킷이라고 추정할 수 있습니다.
